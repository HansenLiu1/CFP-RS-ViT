# Known numerical differences

The release targets exact reproduction of the reported summary values, but a
few implementation details can produce last-digit differences.  They are
listed here rather than hidden by rounding.

## BLAS threading

Several analyses use `numpy.linalg`, SVD and scikit-learn fits.  BLAS thread
counts can change the result at roughly the sixth decimal place.  The paper's
runs used a small fixed thread count per process (3 for the analysis workers).
Set `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS` and `MKL_NUM_THREADS` to `3` if
you need to match the archived values exactly.

## Text encoders and fp16

The S12 text-baseline values were produced with fp16 autocast on the text
tower.  A full-fp32 rerun can differ by about `1.5e-4` macro AP.  The public
configuration records the precision used; do not mix fp16 and fp32 cells in one
summary table.

## fit15 and effective support

`fit15` means "at most 15 direction-fit objects per class in sha256(object_id)
order", followed by removal of near-zero deltas.  Under block masking, some
objects can have a near-zero delta; the effective support can therefore be
lower than 15.  The support is recorded per cell in the exported CSV.

## Magnitude-weighted normalization

The magnitude-weighted variant uses the median norm of the **valid** fit rows
as its reference.  An earlier internal export also included near-zero rows in
that median.  The public implementation excludes them; this changes only a
small number of block-mask cells.

## Figures 1 and 2

Figures 3--7 are generated by matplotlib and are fully scripted.  Figures 1 and
2 are conceptual SVG/PNG assets prepared with a browser exporter; their text
and raster panels are not generated by the analysis pipeline.  Do not treat a
different SVG-to-PNG renderer as a numerical reproducibility check.

## Confidence intervals and margins

Table IV margins and the S13 paired intervals use different weighting
conventions in the manuscript.  The public functions expose the weighting
explicitly (`object` or `source_image`); use the convention named in the table
note rather than silently averaging the two.
